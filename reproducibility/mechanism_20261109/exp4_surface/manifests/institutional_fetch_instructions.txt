3. Retrieval & Reanalysis Procedures
-------------------------------------------------------------------------------

A. Lightweight Frozen-Output Verification (Local, ~2 seconds):
   Does NOT require cluster access, bulk databases, or GPU.
   Recomputes full-universe genus-dereplicated joint BH-FDR (8,760 tests) and
   primary joint BH-FDR directly from raw p-values in the 1,460-family evaluation
   table, verifies model availability partitions, and validates 47 candidate dossiers.
   Run:
       uv run python verify_frozen_outputs.py
       uv run pytest tests/test_exp4_surface.py

B. Full Upstream Reanalysis (Shaheen III Slurm Cluster):
   Requires access to the `k10018` Shaheen project allocation, the `mapping`
   conda environment, Singularity ce/4.3.2, and Foldseek/DIAMOND containers.

   Historical Root Immutability Contract:
   Historical results under `/scratch/project/k10018/eq-mechanism-20261109/exp4_surface`
   are frozen evidence. Entrypoint wrappers strictly refuse execution in the historical root
   (canonicalized via `realpath -m`, rejecting trailing slashes, intermediate dots, and symlinks)
   and refuse pre-existing outputs / .done markers to prevent silent skipping or overwriting.
   Reanalysis is conducted from frozen shard inputs and actual upstream dependencies; exact
   staging is necessary. Reanalysis requires an explicit fresh, empty EQ_EXP4_ROOT directory.

   Execution Procedure:
   1. Stage package code, tests, and manifests from local machine (lc-dell):
      # Use exact fresh path with timestamp/unique suffix to prevent collisions:
      export EQ_REMOTE_ROOT="/scratch/project/k10018/hohndor/reanalysis_$(date +%Y%m%d_%H%M%S)_exp4_surface"

      # Explicitly create remote root and logs/ directory before rsync/sbatch (Slurm requires logs/ to exist beforehand):
      ssh -J ws-ts shaheen "mkdir -p '${EQ_REMOTE_ROOT}/logs'"

      # Stage package code, tests, and manifests:
      rsync -avz -e 'ssh -J ws-ts' \
        /home/leechuck/Public/software/empty-quarter-proteome/reproducibility/mechanism_20261109/exp4_surface/ \
        shaheen:${EQ_REMOTE_ROOT}/

   2. Execute staging preflight via Slurm compute allocation (avoids heavy login node I/O):
      ssh shaheen
      # Use the exact fresh path created above (avoid wildcard cd reanalysis_* which fails if multiple runs exist):
      cd "${EQ_REMOTE_ROOT}" # Or exact /scratch/project/k10018/hohndor/reanalysis_<TIMESTAMP>_exp4_surface
      export EQ_EXP4_ROOT="$PWD"

      # Submit staging preflight job (stages inputs from historical root and verifies SHA256)
      STAGE_JOB=$(sbatch --export=ALL,EQ_EXP4_ROOT="$EQ_EXP4_ROOT" code/sbatch_exp4_stage_preflight.sh | awk '{print $4}')

      The preflight stages immutable assets from the historical root:
      - inputs/task_a_stage1b_all_candidate_member_loci_verified.tsv.gz
      - inputs/curated_role_reference_panel.*
      - inputs/pdb_chains/*.pdb
      - results/shard_inputs/shard_*.pkl (0..16)
      - provenance/frozen_family_universe.tsv
      and verifies shard pickles against the staged relative manifest:
      sha256sum -c "$EQ_EXP4_ROOT/manifests/upstream_shard_bundles.sha256"

   3. Submit dependency-chained reanalysis:
      ARRAY_JOB=$(sbatch --dependency=afterok:${STAGE_JOB} --export=ALL,EQ_EXP4_ROOT="$EQ_EXP4_ROOT" code/sbatch_exp4_array.sh | awk '{print $4}')
      COLLECT_JOB=$(sbatch --dependency=afterok:${ARRAY_JOB} --export=ALL,EQ_EXP4_ROOT="$EQ_EXP4_ROOT" code/sbatch_exp4_collect.sh | awk '{print $4}')
      sbatch --dependency=afterok:${COLLECT_JOB} --export=ALL,EQ_EXP4_ROOT="$EQ_EXP4_ROOT" code/sbatch_exp4_followup_audit.sh
